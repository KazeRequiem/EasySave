# EasySave – Backup Application

## Overview

**EasySave** is a console-based backup application developed in C# using a clean layered architecture.  
It allows users to create, manage, and execute backup jobs using different backup strategies (Full and Differential).

The application supports both:  
- **Interactive mode** (console UI with menus)  
- **Command-line mode (CLI)** for automated execution  

A dedicated logging module, **EasyLog**, records all operations in JSON format.

---

## Features

- Create, modify, delete, list, and execute backup jobs  
- Two backup strategies:  
  - **Full backup**: copies all files  
  - **Differential backup**: copies only new or modified files  
- Interactive console user interface  
- Command-line execution for automation  
- Real-time backup state tracking  
- JSON-based persistence (jobs, states, logs)  
- Multi-language support (English / French)  
- Thread-safe logging and state management  

---

## Architecture

The project follows a **layered architecture** inspired by MVVM and clean architecture principles.

### Main Layers

- **Models**  
  Data structures representing backup jobs, backup states, log entries, and enums.

- **Views**  
  Console-based user interface responsible for user interactions.

- **ViewModels**  
  Acts as an intermediary between the Views and the Services, handling input validation.

- **Services**  
  Contains the core business logic for managing and executing backup jobs.

- **Repositories**  
  Responsible for persistence (reading/writing JSON files).

- **Strategies**  
  Implements different backup behaviors using the **Strategy pattern**.

- **Logging (EasyLog)**  
  Centralized logging system using the **Singleton pattern**.

---

## Design Patterns Used

- **MVVM (simplified)** – separation between UI, logic, and data  
- **Strategy Pattern** – interchangeable backup behaviors  
- **Factory Pattern** – creation of backup strategies  
- **Singleton Pattern** – centralized logging instance  
- **Repository Pattern** – abstraction of data persistence

## Backup Strategies

### Full Backup

- Copies all files from the source directory  
- Preserves directory structure  
- Updates backup progress after each file  

### Differential Backup

- Copies only:  
  - files that do not exist in the destination  
  - files that have been modified since the last backup  
- Faster than a full backup after the first execution  

---

## Backup State Tracking

Each backup execution updates a `BackupState` object containing:

- current state (ACTIVE, END, ERROR)  
- source and destination file paths  
- number of files remaining  
- total files and total size  
- progression percentage  
- last action timestamp  

States are persisted in `state.json`.

---

## Logging System (EasyLog)

- Logs are written in **JSON format**  
- One log file per day  
- Thread-safe logging  
- Each log entry contains:
  - timestamp  
  - operation name  
  - source and destination paths  
  - transferred size  
  - execution time  
  - success or error status  

Logs are stored in the `Logs/` directory.

## Command-Line Usage

The application supports automatic execution via CLI.

### Examples
Executes backup job with ID 1.
```bash
EasySave.exe 1
```
Executes jobs 1 to 3.
```bash
EasySave.exe 1-3
```
Executes jobs 1, 3, and 5.
```bash
EasySave.exe 1;3;5
```

## Localization

The application supports multiple languages:

- **English** (default)
- **French**

The language is selected at application startup and is applied
to all user interface messages.

---

## Data Persistence

EasySave uses JSON files to persist application data.

- `jobs.json`  
  Stores backup job definitions.

- `state.json`  
  Stores real-time and final backup execution states.

- `Logs/yyyy-MM-dd.json`  
  Stores daily log entries generated by the logging system.

All files and directories are automatically created if they do not exist.
